## Offline reproduction

Python 3.10+; standard library only (CI uses Python 3.12). From the repository
root, this single command expands the committed `complete.json` seed, derives
the seven controls, checks their expected labels/reasons and byte-stable reruns,
and writes the expanded inputs, paired JSON/CSV outputs, and `controls.json`:

```sh
python3 -m scripts.q3_synthetic --output-dir /tmp/q3-synthetic
```

Use a dedicated output directory. The command overwrites its 22 named synthetic
artifacts, never the seed or authoritative ledgers. It has no network code and
does not read real-source material, manifests, retrieval logs, or trackers.
Every control must pass before any output is written; a failed control, invalid
input, or I/O error prints an explicit error and exits nonzero.

```sh
python3 -m unittest discover -s tests -p 'test_q3_classifier.py' -v
python3 scripts/validate_data.py
python3 -m unittest discover -s tests -v
git diff --check
```

The full suite includes the controls and separate-process reruns with different
hash seeds/timezones, comparing every generated byte. CI runs both the full
suite and the regeneration command. Generated files need not be committed.
For programmatic use, `scripts.q3_classifier.classify(document)` validates the
entire batch before evaluating reports; `canonical_json` and `csv_output`
serialize the result. `load_json` rejects duplicate keys and nonfinite numbers.
There is deliberately no real-source execution path or readiness switch.

## Minimal data dictionary

The expanded input uses `schema_version: q3-synthetic-v1` and
`synthetic_only: true`. All identifiers must start `SYN-`; real IDs are rejected.
Unknown keys, missing records, duplicate IDs, invalid values/provenance, and
contradictory counts/cohort maps halt, not classify as missing reporting.

| Object | Required contents |
| --- | --- |
| `inventory[]` | One fixed `source_id`, `report_id`, `program_id`, `target_population_id`, `subcohort_id`, `source_version_id` tuple per invented report. No report/version can be counted twice. |
| `sources[]` | Synthetic source/version, `material` (invented field-value map), SHA-256 of its canonical JSON bytes. Reported values must match this material, and versions must match the inventory. This checksum establishes fixture integrity, not scientific truth or real-source approval. |
| `reports[]` | Exact inventory tuple plus `fields[]`. No cross-report, cross-version, or cross-target field borrowing. |
| `overlap[]` | Governing relationship keys: populations, `relationship`, `direction_if_subset`, source version, locator, note. Subset direction is `from_is_subset_of_to`; other relationships use an empty direction. Missing relationships default to `uncertain` within a program. Same/subset reachability cannot contradict a disjoint assertion or form a strict subset cycle. |
| `corrections[]` | Report, field, correction reason, original tracker commit/row/annotation, corrected annotation, source version and locator. Only `LEDGER_EXTRACTION_GAP`, `LEDGER_EXTRACTION_ERROR`, `SOURCE_VERSION_CHANGE`; never consumed by either rule. Synthetic tracker references only. |

Each field has all governing keys: `field_id`, `status`, `value`,
`source_version_id`, `target_population_id`, `subcohort_id`, `locator` (list),
`review_scope`, `reason_codes`, `adjudication_note`. Implementation metadata
adds `review_complete` (Boolean), `access_log` (string), `structural_basis`
(string). Locators use `synthetic://<source_version_id>/<field-or-statement>`.
Annotations and input reason codes are preserved, not used as user-supplied
predicate decisions. Only engine-derived predicate reasons drive labels.

| Field state | Value and evidence contract |
| --- | --- |
| `reported` | Typed, non-null, source-matching value and locator. Zero, false, unfavorable and wrong-horizon values are preserved. |
| `unreported_in_reviewed_material` | Null; completed review of relevant main/supplemental material and locator/scope. The synthetic source must actually omit the field. Confirmed omission is unmet, except missing enrollment proof remains unknown. |
| `inaccessible` | Null; nonempty access log, scope, locator. Unknown, not zero or omission. |
| `not_yet_extracted` | Null; incomplete review, scope, locator. Unknown, not a source reporting failure. |
| `conflicting` | Null; at least two distinct statement locators and a note describing the conflict. Unknown. |
| `not_applicable` | Null; complete review, cited structural rationale in the synthetic material. Allowed only for an endpoint baseline where not meaningful, or independence onset/duration with explicit no-independence-through-horizon evidence. Never waives a domain or denominator. |

The exact executable field inventory is `SPECS` in
`scripts/q3_classifier.py`. The following table maps every field family to the
governing requirements. Counts are nonnegative integers (Booleans rejected);
measurements are finite nonnegative numbers. Text retains source-defined units,
definitions and intervals. No numerical visit conversion or imputation occurs.

| Fields | Type / requirement |
| --- | --- |
| `target_enrolled` | Boolean evidence about the fixed target, separate from results availability. False proves no enrollment; missing/conflicting/inaccessible proof is unknown. Consistent with a reported global enrolled count. |
| `population_identified` | Boolean; P2. |
| `overall_followup` | P3: `month_12`, `day_365`, `week_52`, `later_only` pass; `below_12_months`, `maximum_only`, `unspecified` do not establish the screen horizon. |
| `followup_attribution` | P3: `target`, `contextual` (unmet), `uncertain` (unknown). |
| `other_evidence` | `none`, `surrogate_only`, `qualitative_only`; explains P1 failure, never supplies an observed clinical endpoint. |
| `identity.{population,disease_stage,eligibility,intervention,dose,design,baseline_context,comparator,mapping}` | H1 source-defined text, including explicit absence of comparator where appropriate. |
| `identity.linkage` | H1: `verified`, `uncertain` (unknown), `contextual` (unmet); detailed linkage is not a provisional requirement. |
| `counts.{enrolled,treated,followed,at_horizon,censored,withdrawals}` | H3 distinct global counts, with consistent ordering. No sums across reports. |
| `counts.missing_data_handling` | H3 text; explicit none accepted, silence not accepted. |
| `treatment.{first_administration,repeat_administrations,source_anchors}` | H5 retains first/repeat dates, procedures, doses/exposures and source-stated anchors as text, including explicit no repeats. H4 endpoint anchors are tested separately. No derived reanchoring. |
| `burden.{immunosuppression,exposure,co_interventions,repeat_procedures}` | H5 text including source-defined regimen, exposure and explicit absences. |
| `safety.{harms,population,window,attribution,discontinuations}` | H5 text; no inference of safety from silence. |
| `independence.none_through_horizon` | Conditional Boolean proof for onset/duration inapplicability, not an extra mandatory reporting gate when onset/duration are reported. Zero at the horizon alone is insufficient. |
| `independence.{onset,duration}` | H2 source-defined text, or justified structural inapplicability. |
| `<endpoint>.{observation,attribution,value}` | `observation`: `observed`, `planned`, `none`; attribution: `target`, `contextual`, `uncertain`. Value: quantitative measurement/count. P1 is an OR over observed numeric target-attributed endpoints (including hypoglycemia events or affected participants), not a preassigned predicate. H2 requires every endpoint observed, H1 its target linkage. |
| `<endpoint>.{baseline,definition,hierarchy}` | H2 baseline number where meaningful, definition text, hierarchy `primary`, `secondary`, `post_hoc`, `composite`. |
| `<endpoint>.{denominator,denominator_basis}` | H3 analysis count; only `endpoint_analysis` is a valid participant analysis denominator. `enrollment`, `device_count`, and `other_endpoint` fail with `DENOMINATOR_MISSING`, even if numerically identical. Enrollment bounds, numerator-versus-denominator checks, affected-participant-versus-denominator checks, and integer-count feasibility checks for reported percentages with unavailable numerators apply only when the basis is `endpoint_analysis`, because those values are participant counts. In particular, a device count can exceed participant enrollment without an input error, but is never accepted as the H3 denominator. |
| `<continuous>.{units,summary}` | H3 source-defined units and summary text; not extra requirements for binary independence/event counts. |
| `<endpoint>.{horizon,anchor}` | H4 only `month_12`, `day_365`, `week_52` and `first_cell_administration` pass. `month_6`, `later_only`, `maximum_only`, `through_one_year` fail horizon. `repeat_administration`, `independence_onset`, `empty_device_implantation` fail anchor; `unspecified` anchor fails as unreported timing. |
| `<endpoint>.{analysis_population,population_link}` | H4: `target` or `documented_attrition_subset` with source-defined linkage text; `contextual` fails, `uncertain` is unknown. No substitution of another cohort. |
| `<endpoint>.{interval_start,interval_end}` | H4 source-defined start text and nominal end label. End must be an accepted horizon; `month_6` and `later_only` fail with `WINDOW_MISMATCH`; `unspecified` fails with `TIMING_UNREPORTED`. A point assessment can use its source-defined assessment interval. Event intervals retain start/end plus the endpoint denominator. |
| `cgm.{range,aggregation_interval}` | H2: literal `70-180 mg/dL` and source-defined aggregation text. |
| `severe_hypoglycemia.participants_affected` | H2 affected count, bounded by analysis denominator and event count; events are not assumed to equal affected participants. |

`<endpoint>` means `insulin_dose`, `insulin_independence`, `hba1c`, `cgm`,
`severe_hypoglycemia`; `<continuous>` means insulin dose, HbA1c, CGM.
Independence value is its binary numerator; hypoglycemia value is event count.
Definitions and population/interval/linkage text are adjudicated source facts,
not natural-language claims that the engine can independently verify.

## Classification and output contract

Both rules consume the same validated record once. Predicate states are
`met`, `unmet`, `unknown`. Provisional P1 is at least one quantitatively
observed target-attributed endpoint; P2 identifiable target; P3 overall
target-attributed nominal follow-up, accepting later-only follow-up without
an endpoint-specific anchor requirement. Harmonization includes those exact
predicates plus H1-H5. Failure reasons use only governing v1.1 codes.

Precedence is exact: proven no enrolled target gives `not_applicable`;
otherwise any required unmet predicate gives `not_supported`; otherwise any
unknown gives `unresolved`; only all met with proven enrollment gives
`supported`. Every failure reason and unknown field flag is retained even
beneath a higher-precedence label. Harmonized-supported implies
provisional-supported; a reverse transition halts.

JSON (`q3-synthetic-output-v1`) contains paired labels, predicate states/reasons,
all ordered field facts/provenance and source-material SHA-256, unknown flags, conservative program
coverage/relationship evidence, separate correction log and governing-rules
SHA-256. Reports sort by program then report, fields by field ID, codes and
locators lexically. Sorted coverage preserves subset direction, including
`to_is_subset_of_from` when the original source-to-target ordering is reversed.
Coverage has no program vote, unique-participant estimate,
or participant total. CSV is a fixed ordered summary:

```text
program_id,report_id,source_id,source_version_id,target_population_id,subcohort_id,provisional-v1.1,harmonized-v1.1,provisional_reasons,harmonized_reasons,unknown_fields
```

The seven control names in `controls.json` are `complete_unfavorable`,
`missing_denominator`, `duplicate_cohort`, `timing_anchor_mismatch`,
`planned_only`, `inaccessible`, `ledger_only_extraction_gap`. The timing control
retains both mismatch reasons; tests also isolate each window/anchor change.
The access control retains both `SOURCE_INACCESSIBLE` and
`TARGET_ENROLLMENT_UNKNOWN`. The ledger gap appears only in the correction log.
Tests cover the amendment clarifications, all field families, all labels and
states, failures before uncertainty, schema/provenance stops, and 19,683
combinations of enrollment/P1-P3/H1-H5 predicate states.

## Independent-review boundary and limitations

Passing synthetic checks is evidence for review, **not certification of G2
readiness**. A reviewer must explicitly accept the controls, invariants,
classification and reproducibility before Issue #34 or any real-source
outcome work. Do not merge automatically. This implementation intentionally
rejects actual IDs; a separately authorized future change would need to bind
real-source facts to the frozen accepted inventory and permitted versions.

The engine validates types, consistency and fixture provenance, not the
truth/completeness of human source review or the semantics of narrative
definitions, baseline rationales, dates, attrition links or safety annotations.
Source-specific adjudication remains independent-review work. Synthetic
checks do not resolve S19/S23 rights/access limitations or PEC-Direct overlap.
No eight-report research transition table, robustness fraction, sensitivity
analysis, real extraction ledger, or research conclusion is produced here;
those remain downstream gated work under the unchanged preregistration.

## PR review correction and field-mapping audit (24 October 2026)

The follow-up attribution dispatch now names `followup_attribution` explicitly,
alongside the endpoint `.attribution` enum fields: `target` is met,
`contextual` is unmet with `TARGET_POPULATION_MISMATCH`, and `uncertain` is
unknown with `TARGET_ATTRIBUTION_UNCERTAIN`. Isolated tests change only that
field from the complete baseline, preserving every endpoint's target
attribution, and assert P3, both labels, both reason lists, and unknown flags.
Inaccessible, conflicting and incomplete-review variants remain unknown.
At the reviewed commit `f258b27`, the broader suffix test already matched
`followup_attribution`; the alleged default-to-met behavior was not reproduced.
The explicit dispatch removes the naming ambiguity and the isolated regressions
close a test gap previously masked by simultaneous endpoint attribution changes.

The audit traced the declared field families to P1-P3/H1-H5, checked every enum
choice and special Boolean/CGM-range branch, and checked state handling and
the deliberate cross-field uses of `other_evidence` and
`independence.none_through_horizon`. Narrative fields remain adjudicated text,
not independently machine-verifiable claims. No further naming-dispatch or
predicate omission was identified.

Two related consistency defects, also raised by Copilot review, were confirmed
and corrected: proven no target enrollment now rejects positive global target
counts even when intermediate counts are unknown; contextual or uncertain
endpoint denominators are no longer bounded by the fixed target's enrollment.
Only target-attributed denominators receive that bound. Endpoint-local
numerator/denominator and event/affected-participant checks remain enforced.
Tests retain contextual observations under a proven un-enrolled target and
verify that their presence does not prevent `not_applicable` precedence.
These corrections do not change governing rules, source facts, or authorization.

Subsequent review identified additional no-enrollment consistency edge cases.
An observed, target-attributed endpoint now contradicts proven zero enrollment
regardless of whether its numeric value or denominator is accessible. A positive
target analysis denominator also contradicts that proof when observation status
is unknown; explicitly planned endpoints remain exempt from the actual-enrollment
bound. Contextual-cohort observations remain permitted and retain their flags.
Global followed/horizon counts are checked against all known ancestors, not
just adjacent counts, so unknown intermediate counts cannot conceal a proven
contradiction. A reported global enrolled count of zero supplies no-enrollment
proof for label precedence even when `target_enrolled` is unknown; its original
unknown field flag and other uncertainty/failure reasons remain visible.

The review-corrected suite has 202 tests, including 117 classifier tests.
All seven controls and separate-process deterministic regeneration remain
required. These checks do not constitute independent G2 acceptance.

For comparable participant-analysis percentages, the engine verifies that at
least one integer numerator within the stated rounding tolerance is possible
when the numerator is unavailable; a positive percentage must have at least
one possible participant, and the engine does not infer or populate that count.
An observed target-attributed continuous endpoint result supplies evidence of
target enrollment for provisional screening, but does not reconstruct global
counts or relax harmonized denominator requirements. An observed target-
attributed continuous screen quantity also supplies this provisional
enrollment evidence for insulin dose, HbA1c and CGM, including signed changes;
unknown counts remain unknown.

Denominator consistency is basis-aware: a reported `endpoint_analysis` count
is interpreted as participants and, when target-attributed, cannot exceed the
known enrolled target count. Participant numerators/affected counts are
compared with that denominator only when both quantities are participant
counts. A `device_count` is not compared numerically with participants and
does not become a valid analysis denominator; classification fails H3 with
`DENOMINATOR_MISSING`. Other invalid bases likewise remain H3 failures.
Actual observed target-participant outcomes still contradict proven zero
target enrollment, and planned/contextual denominator exceptions remain as
above. Synthetic regressions cover 10 enrolled / 20 devices (screen supported,
harmonized not_supported), the corresponding 20-person analysis denominator
(validation error), each denominator basis, and participant/event count
checks only where units are comparable.

Independently of denominator basis or availability, observed target-attributed
insulin-independent and severe-hypoglycemia-affected participant counts cannot
exceed known target enrollment. Device-based or inaccessible denominators do
not suppress this participant-versus-participant contradiction check. Planned
and contextual outcomes are exempt from this target bound, and unknown
enrollment is not imputed. Hypoglycemia event counts are never bounded by
participant enrollment: repeated events in one participant are permissible.

H3's count reaching the horizon also constrains H4's comparable point
assessments: observed target-attributed insulin-dose, HbA1c and CGM participant
analysis denominators at an accepted nominal horizon, ending at that horizon
and anchored to first cell administration, cannot exceed known
`counts.at_horizon`. This includes documented attrition subsets linked to the
target. Zero horizon completers therefore contradict ten observed month-12
HbA1c participants. Unknown counts are not imputed, and this bound is not
applied to planned/contextual data, device denominators, or different/unknown
windows or anchors. Cumulative severe-hypoglycemia and independence-episode
interval populations are not bounded by point-assessment completers; events
and episodes may occur before participants withdraw. Narrative source
definitions and window compatibility still require human adjudication.

A confirmed omission of H1 `identity.linkage` uses
`IDENTITY_DESIGN_MISSING`; reported uncertain linkage continues to use
`COHORT_LINKAGE_CONFLICT` with an unknown predicate. This corrects a
reason-code mismatch identified in review without changing either rule.

Optional `<endpoint>.screen_quantity` records preserve additional quantitative
screen evidence as `{"value": 0.25, "units": "proportion"}` (or source-stated
percent/rate units), with the same status and provenance requirements as other
fields. They are separate from mandatory harmonized counts and participate
only in P1, together with observed status and target attribution. Absence of
this optional representation does not create missingness; a provided unknown
record retains its uncertainty flags. No counts, denominators or unit
conversions are reconstructed from it. A proportion-only observation can pass
the permissive screen while confirmed missing counts/analysis denominators
still fail harmonization. The complete synthetic seed need not invent
additional screen quantities.
Insulin-independence and severe-hypoglycemia quantities must be nonnegative;
insulin-dose, HbA1c and CGM quantities may be finite signed changes (either
sign is quantitative evidence). An independence quantity above zero contradicts
explicit `independence.none_through_horizon=true` and halts validation.
Optional `measure` and `window` metadata must be supplied together when
declaring quantity semantics. Cross-field consistency checks use such a
quantity only when its measure and window explicitly match the corresponding
endpoint facts; generic units alone are not treated as proof of comparability.
For affected-participant percentages, a comparable percentage is checked
against the observed affected count and endpoint-analysis denominator, allowing
up to 0.5 percentage points for source rounding. Independence absence applies
to its through-horizon window and does not contradict explicitly later-window
evidence. Contradiction checks for independence counts or quantities also
require observed, target-attributed evidence in the target or documented
attrition-subset analysis population; planned/contextual evidence is retained
but not treated as a contradiction.
Endpoint-relative percentage comparisons additionally require accepted
nominal horizon and interval-end values and the first-cell-administration
anchor; `month_12`, `day_365`, and `week_52` are equivalent nominal labels and
need not be textually identical.
Comparable point-assessment denominators are also bounded by each known
participant-count ancestor (enrolled, treated, followed, and at-horizon);
unknown intermediate counts do not hide contradictions with a known ancestor.
For comparable hypoglycemia percentage evidence, proven zero events requires
zero affected percentage even when the affected-participant count is unknown.
Independence percentages are checked against the positive numerator and
participant-analysis denominator with the same rounding tolerance.
Affected-participant percentages are bounded to 0–100% and proportions to 0–1.
These participant-percentage bounds do not reject signed HbA1c, CGM, or
insulin-dose changes, including explicitly named measures such as
`hba1c_change_percentage`; positive and negative signed percentage changes are
accepted as screen evidence but do not replace a missing absolute endpoint
result for harmonization. A zero observed independence count conflicts with a
positive percentage for the same target assessment even if its denominator is
unavailable or not a participant-analysis denominator; percentage arithmetic
still requires a valid participant-analysis denominator.
Percentage comparisons normalize `%`, `percent`, `percentage`, `proportion`,
and `fraction` to percentage points while preserving their original values and
units in output. Exact-zero count conflicts are not relaxed by the rounding
tolerance used for nonzero count comparisons. When an affected-participant
count is inaccessible, the feasible integer count interval applies that same
0.5-percentage-point tolerance, with only a scale-bounded floating-point
epsilon before `ceil`/`floor` so equivalent percentage and proportion inputs
remain equivalent at a rounding boundary.

Observed, target-attributed, first-cell-administration binary endpoints with a
compatible target/attrition analysis population are checked against a known
treated count: both the participant numerator and `endpoint_analysis`
denominator cannot exceed it, even when the assessment is explicitly earlier
or later than the nominal horizon. Timing determines harmonized eligibility,
not whether the same treated cohort could contain more participants than were
treated. This does not compare cumulative hypoglycemia
event totals with participants; event totals may exceed the treated count, while
the affected-participant numerator and participant-analysis denominator may
not. The cumulative event denominator is not bounded by the point-in-time
horizon-completer count. Planned or contextual observations and device-count
bases do not trigger participant-unit checks; device bases still fail H3.
Unknown treated counts remain unknown and do not cause inferred values.

A source-reported positive `counts.enrolled` now proves aggregate enrollment
even when `target_enrolled` is unknown. Positive observed target-attributed
participant-analysis denominators, insulin-independence counts, and
hypoglycemia affected-participant counts also establish that some target
participants enrolled. A positive observed target-attributed hypoglycemia
event count is likewise evidence that target participants enrolled, but does
not reconstruct the number affected or any denominator. Planned or contextual
observations and device denominators do not. The Boolean and missing
enrolled-total unknown flags are
preserved, so harmonization remains unresolved when required global counts are
unknown. With no such proof, enrollment remains unknown; a reported zero
establishes no-enrollment precedence. Schema/provenance validation does not
establish the truth or completeness of source review. Positive observed,
explicitly identified target insulin-independence or affected-participant
percentages also prove that some participants enrolled without reconstructing
their counts; the unknown count flags remain and harmonization remains
unresolved when required denominators/counts are unavailable.
